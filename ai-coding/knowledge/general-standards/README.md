# 企业级通用规范

## 规范体系概览

本目录包含企业级软件开发的通用规范文档，涵盖项目管理、代码评审、文档编写、数据管理等方面。

## 规范清单

### 1. 项目管理规范
**文件**：[01-project-management.md](./01-project-management.md)

**适用场景**：项目规划、迭代管理、风险控制、质量保障

**核心内容**：
- 需求管理与变更控制
- 迭代规划与每日站会
- 风险识别与跟踪
- 质量目标与检查点
- 发布管理与回滚
- 项目复盘与度量指标

**关键原则**：
- 需求必须文档化，口头需求无效
- 变更需评审审批，控制范围蔓延
- 风险早识别早应对，定期跟踪
- 质量内建，每个环节都有检查点

---

### 2. 代码评审规范
**文件**：[02-code-review.md](./02-code-review.md)

**适用场景**：代码合并前的质量把关

**核心内容**：
- 评审流程（提交→检查→反馈→修改→合并）
- 评审检查项（规范、设计、功能、安全、性能）
- 评审分级（Blocker/Major/Minor/Info）
- 评审工具（GitLab/GitHub + SonarQube）
- 评审最佳实践

**关键原则**：
- 所有代码必须评审，无例外
- 评审意见24小时内反馈
- 对事不对人，建设性反馈
- Blocker = 0 才能合并

---

### 3. 文档规范
**文件**：[03-documentation.md](./03-documentation.md)

**适用场景**：技术文档编写与维护

**核心内容**：
- 文档体系（产品文档、技术文档、开发文档、运维文档）
- PRD模板与技术方案模板
- 接口文档规范（Swagger/Markdown）
- 数据库设计文档（ER图、字段说明）
- README编写规范
- 部署运维文档

**关键原则**：
- 文档与代码同步更新
- 每个文档有版本管理
- 敏感信息不写入文档
- 文档有明确责任人

---

### 4. 数据管理规范
**文件**：[04-data-management.md](./04-data-management.md)

**适用场景**：数据安全、隐私保护、合规管理

**核心内容**：
- 数据分类与敏感级别
- 敏感数据加密与脱敏
- 数据访问权限控制
- 数据备份与恢复
- 数据清理与归档
- 个人信息保护（GDPR/PIPL）

**关键原则**：
- 敏感数据必须加密存储
- 对外展示必须脱敏
- 访问必须鉴权+审计
- 定期备份+恢复演练
- 遵守数据合规要求

## 规范使用指南

### 适用人群
- **开发人员**：必读所有规范
- **产品经理**：重点阅读项目管理、文档规范
- **测试人员**：重点阅读项目管理、代码评审
- **运维人员**：重点阅读文档规范、数据管理

### 学习路径
1. **新人入职**：按顺序阅读全部规范
2. **日常开发**：作为查询手册使用
3. **Code Review**：对照评审规范检查
4. **项目启动**：参照项目管理规范制定计划

### 强制执行
以下规范为强制执行项，违反将阻止代码合并或发布：
- ✅ 代码评审100%覆盖
- ✅ 敏感数据必须加密
- ✅ 接口必须有文档
- ✅ 变更必须走审批流程
- ✅ 生产发布必须有回滚方案

### 建议执行
以下规范为建议执行项，鼓励团队遵守：
- 💡 单元测试覆盖率≥80%
- 💡 每周进行项目周会
- 💡 每月进行技术分享
- 💡 每季度进行备份恢复演练

## 规范维护

### 更新机制
- **定期更新**：每季度评审一次，优化规范内容
- **按需更新**：发现问题或有新要求时及时更新
- **版本管理**：每次更新记录修订历史

### 反馈渠道
- 技术委员会会议
- 项目复盘会议
- 内部Wiki讨论区
- 邮件：tech-standard@example.com

### 豁免机制
特殊情况下（紧急修复、技术预研）可申请规范豁免：
1. 提交豁免申请，说明理由
2. 技术负责人审批
3. 事后补充完整流程

## 工具支持

### 自动化检查
- **代码规范**：Checkstyle、ESLint、Pylint
- **代码质量**：SonarQube
- **安全扫描**：OWASP Dependency Check
- **文档生成**：Swagger、DbDoc

### CI/CD集成
```yaml
# .gitlab-ci.yml 规范检查示例
standards_check:
  stage: check
  script:
    # 代码规范检查
    - mvn checkstyle:check
    
    # 代码质量扫描
    - sonar-scanner
    
    # 安全漏洞扫描
    - mvn dependency-check:check
    
    # 文档完整性检查
    - ./scripts/check-docs.sh
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
```

## 常见问题

### Q1: 规范太多记不住怎么办？
A: 不需要全部记住，重点掌握核心原则，日常开发时当作查询手册使用。IDE插件和CI检查会自动提醒大部分问题。

### Q2: 规范与实际情况不符怎么办？
A: 可以通过反馈渠道提出，技术委员会会定期评审。特殊情况可申请豁免。

### Q3: 新项目要全部遵守所有规范吗？
A: 根据项目规模和重要性分级执行。核心业务必须全部遵守，内部工具可适当简化。

### Q4: 旧项目如何应用这些规范？
A: 增量应用，新代码严格遵守规范，旧代码逐步重构。重点模块优先改造。

### Q5: 规范执行不到位怎么办？
A: 通过自动化工具 + Code Review + 定期审计三层保障。持续违反规范纳入绩效考核。

## 总结

企业级规范的核心目标是**提升质量、降低风险、提高效率**。遵守规范不是增加负担，而是减少返工、避免线上故障、提升团队协作效率的最佳实践。

**记住**：规范不是束缚，而是护栏。规范保护的不是代码，而是我们自己。
